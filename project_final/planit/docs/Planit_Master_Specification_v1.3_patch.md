## 2.3 `GET /api/month/?year=2026&month=10&area=all|academic|personal&exam_mode=0|1`

```json
{
  "meta": {"today": "2026-10-06", "timezone": "Asia/Bangkok", "exam_window_days": 14},
  "year": 2026,
  "month": 10,
  "first_weekday": 3,
  "days": [
    {
      "date": "2026-10-09",
      "counts": {"total": 2, "exam": 1, "overdue": 0, "academic": 1, "personal": 0, "completed": 0},
      "dots": ["exam", "academic"],
      "tasks": [ /* task objects เหมือน /api/tasks/ */ ]
    }
  ]
}
```

- Python สร้างครบทุกวันของเดือน (28–31) วันว่างมี `counts` เป็น 0 และ `tasks: []`
- ใช้ `group_by_date()` ตัวเดิม แต่รับช่วง `(month_start, month_end)` แทนสัปดาห์ (ฟังก์ชันรับ `start, end` อยู่แล้วตาม v1.2 §6)
- `dots` เรียงลำดับตามความสำคัญ: exam → overdue → academic → personal → completed
- overdue จากก่อนเดือนนี้ **ไม่แสดงในช่อง** (เหมือน This Week) แต่แสดงแถบสรุปด้านบนหน้า: "มี N งานเลยกำหนด"
- past exam แสดงแบบจางเหมือน This Week
- parameter ผิด (เดือน 13, ปีนอกช่วง 2000–2100, area ไม่รู้จัก) → 400
- ใช้ `select_related`; ต้องผ่าน `assertNumQueries` (≤ 3)
- JS ใช้ `meta.today` เท่านั้นในการไฮไลต์วันนี้ (กฎ v1.2 §7.1)

## 3.3 OOP: `Module` ABC และ registry (อยู่ใน `modules.py` แยกจาก `domain.py`)

```python
from abc import ABC, abstractmethod

class Module(ABC):
    key: str            # "habits"
    title: str          # "Habits"
    description: str    # ข้อความใน onboarding
    keep_in_exam_mode = False

    @abstractmethod
    def today_card(self, user, today):
        """ข้อมูลการ์ดบน Today หรือ None ถ้าไม่มีอะไรต้องแสดง"""

    def nav_item(self):
        return {"key": self.key, "title": self.title, "url": f"/{self.key}/"}


MODULE_REGISTRY = {}

def register(cls):
    MODULE_REGISTRY[cls.key] = cls()
    return cls
```

- `build_today_payload` วนเฉพาะโมดูลที่ผู้ใช้เปิด แล้วเรียก `module.today_card(user, today)` เหมือนกันทุกตัว → ได้ `modules: [{key, title, card}]` โดยไม่มี `if key == ...`
- เพิ่มโมดูลใหม่ = เพิ่มคลาสหนึ่งตัว + หนึ่ง `@register` + template (ตอบคำถามอาจารย์ "ถ้าเพิ่มสิ่งใหม่ต้องแก้อะไร")
- Exam Mode: โมดูลที่ `keep_in_exam_mode = False` ซ่อนการ์ดบน Today; `FaithModule` เป็น `True` (จุดยึดละหมาดแสดงเสมอ ไม่ถูกซ่อนเพราะ Exam Mode)
- ใน v1 registry ว่างเปล่าได้ แต่ต้องมีโค้ด, `UserSettings`, API และ test ครบ — นี่คือ **หลักฐานสถาปัตยกรรม** ตอน present

## 3.4 API

| Endpoint | วิธี | หน้าที่ |
|---|---|---|
| `/api/settings/` | GET, PATCH | อ่าน/แก้ `UserSettings` (ตรวจบนสถานะหลัง merge ตามกฎ v1.2 §8.1) |

## 3.5 Onboarding (ข้อเดียว)

- แสดงครั้งแรกหลังสมัคร/ล็อกอิน ถ้า `onboarding_done = False`
- เนื้อหา: "อยากใช้อะไรเพิ่มไหม? (เปลี่ยนทีหลังได้)" รายการช่องติ๊กจาก `/api/modules/` ปิดทั้งหมดเป็นค่าเริ่มต้น
- ปุ่มเดียว: "เริ่มใช้เลย" (ข้ามได้) ไม่มีขั้นตอนอื่น
- เมื่อไม่มีโมดูลในระบบ (v1) ข้าม onboarding ไปเลย
- หลังจบ: เปิดหน้า Today ที่มีสถานะว่างพร้อมปุ่ม "เพิ่มงานแรก" และตัวเลือก "ใส่ข้อมูลตัวอย่าง" (เรียก seed สำหรับผู้ใช้นั้น)

## 3.6 การนำทาง

- เดสก์ท็อป: แถบข้างมี 4 แท็บหลัก + หัวข้อ "เพิ่มเติม" แสดงเฉพาะโมดูลที่เปิด

|---|---|
| `Habit` | owner, name (1–100), cadence (`daily` / `weekly`), target_per_period (daily = 1; weekly = 1–7), archived, created_at |
| `HabitLog` | habit, date, UniqueConstraint(habit, date) |

## 5.2 กฎ

- Daily: ทำแล้ว/ยัง ต่อวัน; Weekly: นับจำนวนวันที่ทำในสัปดาห์ (ตามแนว `week_start`) เทียบ target
- **Streak** = จำนวนวัน (หรือสัปดาห์) ติดกันที่ทำถึงเป้า; พลาดวันเดียว streak กลับเป็น 0 แต่เก็บ `best_streak`
- ใช้ถ้อยคำเป็นกำลังใจ ไม่ทำให้รู้สึกผิด: ไม่แสดง "คุณพลาด" ให้แสดง "เริ่มใหม่วันนี้ได้"
- ไม่ย้อนบันทึกเกิน 7 วัน (กันคีย์แก้ตัวเลข) แก้ได้ที่หน้า habit
- ฟังก์ชันบริสุทธิ์: `current_streak(dates, cadence, today, target)`, `week_progress(...)` (ใช้ `reduce`/comprehension)

## 5.3 API

`GET/POST /api/habits/`, `PATCH/DELETE /api/habits/<id>/`, `POST /api/habits/<id>/log/` (body `{"date": "...", "done": true}`; ทำซ้ำได้ = idempotent)

## 5.4 UI

- การ์ดบน Today: "Habits วันนี้ 2/3" พร้อมปุ่มติ๊กเร็ว (ปุ่มละ ≥ 44 px)
- หน้า Habits: รายการ + แถบ 7 วันล่าสุด + streak; **ไม่มี** กราฟซับซ้อน
- Exam Mode: การ์ดซ่อน (`keep_in_exam_mode = False`) ยกเว้นผู้ใช้ติ๊ก "คงไว้ในช่วงสอบ" ต่อ habit (field `keep_in_exam_mode` ของ Habit)

# 6. โมดูล Reading (v1.5)

**ปัญหาที่แก้:** ติดตามการอ่านหนังสือเรียน บทความ และอัลกุรอาน ด้วยหน่วยที่ต่างกัน

## 6.1 โมเดล

| Model | Field |
|---|---|
| `ReadingItem` | owner, title, kind (`book` / `article` / `quran`), unit_label (`pages` / `chapters` / `juz` / `surah`), total_units (> 0), subject (null), target_date (null), finished |
| `ReadingLog` | item, date, units (> 0), note (≤ 200) |

## 6.2 กฎ

- ความคืบหน้า = `sum(units) / total_units` (ไม่เกิน 100%; ถ้าบันทึกเกินให้ตรึงที่ 100 แล้ว `finished = true`)
- **pace** (ถ้ามี `target_date`): `units_per_day_needed = remaining / max(days_left, 1)` ปัด 1 ทศนิยม; ผ่านเส้นตายแล้วไม่ขึ้น pace
- ชนิด `quran`: ตั้งค่า preset ให้ (`juz` ทั้งหมด 30) ผู้ใช้เปลี่ยนหน่วยได้ — ไม่บังคับรูปแบบการอ่าน
- ฟังก์ชันบริสุทธิ์: `reading_progress(logs, total)`, `required_pace(total, read, target_date, today)`

## 6.3 API และ UI

`GET/POST /api/reading/`, `PATCH/DELETE /api/reading/<id>/`, `POST /api/reading/<id>/log/`
การ์ด Today: "อ่านต่อ: {title} — เหลือ N หน้า" ปุ่มเดียว "+ บันทึกที่อ่านวันนี้" (ช่องตัวเลขเดียว)
Exam Mode: ซ่อน ยกเว้นรายการที่ผูก `subject` ซึ่งมี exam ในช่วง 14 วัน (แสดงเป็น "อ่านเพื่อสอบ")

## 6.4 Tests

progress ปกติ / เกิน 100 / `required_pace` เมื่อ days_left = 0 / ผ่านเส้นตาย / ลบ log แล้ว progress ลดลง / preset quran

# 9. โมดูล Faith (v2)

โมดูลนี้ทำให้ Planit ตอบโจทย์นักศึกษามุสลิมจริง ไม่ใช่แค่ตกแต่ง ทุกส่วนเปิด/ปิดแยกกันได้ใน Settings

## 9.1 ส่วนประกอบ

| ส่วน | เปิดเป็นค่าเริ่มต้นเมื่อเปิดโมดูล | หมายเหตุ |
|---|---|---|
| เวลาละหมาด 5 เวลา + พระอาทิตย์ขึ้น | ใช่ | แสดงเป็น "จุดยึดของวัน" ไม่ใช่ task |
| วันศุกร์ (ญุมุอะฮ์) | ใช่ | แถบเด่นบน This Week / Month |
| วันที่ฮิจเราะห์ | ใช่ | แสดงควบคู่วันที่ปกติ; ปรับ ±2 วันได้ |
| โหมดรอมฎอน | อัตโนมัติเมื่อถึงช่วงที่คำนวณ | เปิด/ปิดเอง และกำหนดวันเริ่มเองได้ |
| บันทึกการละหมาดรายเวลา | **ไม่** | ตัวเลือกส่วนตัว (ข้อ 36) |
| วันอีด / วันสำคัญ | ใช่ | แสดงเป็นจุดบนปฏิทินเดือน |

อัลกุรอานและซิกร์ใช้ Reading (`kind = quran`) และ Habits ตามปกติ — Faith เสนอ **preset** ให้เลือก ไม่สร้างโมเดลซ้ำ

## 9.2 การคำนวณเวลาละหมาด

- **ผู้ใช้เลือกเมือง/พิกัดเอง** (ค้นจากรายชื่อเมืองหรือกรอกพิกัด); ไม่บังคับใช้ geolocation ของเบราว์เซอร์ และไม่ส่งพิกัดไปบุคคลที่สาม
- **ผู้ใช้เลือกวิธีคำนวณ** (`prayer_method`) และวิธี Asr (`asr_method`: Standard/Hanafi) — ไม่มีค่าเริ่มต้น; จนกว่าจะเลือกให้แสดงข้อความ "เลือกวิธีคำนวณเพื่อดูเวลาละหมาด" แทนการเดา เพราะต่างกันได้หลายนาทีและเป็นเรื่องที่ชุมชนยึดถือต่างกัน
- วิธีทำ: เลือกใช้ **ไลบรารีคำนวณแบบออฟไลน์** (pin เวอร์ชัน, ตรวจใบอนุญาต, ระบุใน `THIRD_PARTY_NOTICES.md`) เป็นทางหลัก; ถ้าจะใช้ API ภายนอกให้เป็นทางเลือก พร้อม cache รายวันและ fallback เมื่อออฟไลน์ — **ต้องตรวจสอบรายชื่อวิธีคำนวณและค่าของแต่ละวิธีกับเอกสารของไลบรารี/API จริงก่อนใส่ในโค้ด** ไม่เขียนจากความจำ
- ตรวจกับตารางเวลาของหน่วยงานศาสนาในพื้นที่ผู้ใช้อย่างน้อย 3 เมือง/3 วันที่ก่อนปล่อย และบันทึกผลในรายงาน (Testing)
- domain: `PrayerTimes` เป็น value object (ไม่แตะ DB) รับ `(date, lat, lng, method, asr)` คืนเวลา 6 ค่า; `NextPrayer` คำนวณ "ละหมาดถัดไปและเหลืออีกกี่นาที" จาก `now` ที่ server ส่งเข้ามา (ห้ามใช้เวลาเบราว์เซอร์ตัดสิน เหมือนกฎ v1.2 §7.1)

## 9.3 วันที่ฮิจเราะห์และรอมฎอน

- ใช้ไลบรารีแปลงปฏิทินฮิจเราะห์ (pin เวอร์ชัน) + `hijri_offset` ของผู้ใช้ เพราะวันที่จริงขึ้นกับการประกาศในแต่ละพื้นที่ ต่างกันได้ ±1–2 วัน
- **หน้าตั้งค่าต้องบอกตรงๆ ว่าเป็นวันที่โดยประมาณ** ให้ปรับตามประกาศท้องถิ่น
- โหมดรอมฎอน (เมื่อเปิดใช้):
  - แสดง "วันที่ N ของรอมฎอน" บน Today
  - เสนอ **ช่วงอ่านหนังสือที่แนะนำ** เป็นข้อความเฉยๆ (หลังอิฟตาร์ / ก่อนซุบหฺ) ไม่จัดตารางให้เอง
  - แสดงเวลาละเว้นอาหาร (ซุบหฺ–มัฆริบ) บน Today
  - ถ้ามี exam ภายในช่วงรอมฎอน ให้ขึ้นแถบแจ้ง "สอบ {วิชา} ตรงกับรอมฎอน" บน Today และ Month
  - ไม่มีการตัดสินว่าผู้ใช้ "ควร" ปฏิบัติอย่างไร (มีข้อยกเว้นหลายกรณี)

## 9.4 การแสดงบน Today และ Week

- Today: การ์ด "ละหมาดถัดไป: อัศรฺ 15:12 (อีก 42 นาที)" คลิกเปิดรายการเวลาทั้งวัน
- This Week / Month: จุดยึดเป็นแถบเล็กในช่องวัน ไม่ปนกับ task และไม่ถูกนับใน progress/aggregate
- การชนกันของเวลา: ใน v1.x งานไม่มีเวลาเริ่ม จึงไม่มี "ชนกัน" ให้ตรวจ — ระบุเป็น limitation และ Future Work เมื่อเพิ่ม time-blocking
- Exam Mode: จุดยึดละหมาด **ไม่ถูกซ่อน** (`keep_in_exam_mode = True`)

## 9.5 ความเป็นส่วนตัวและความระมัดระวัง

- ข้อมูลศาสนาเป็นข้อมูลอ่อนไหว: เก็บเฉพาะที่จำเป็น (เมือง/พิกัดที่ผู้ใช้เลือก, วิธีคำนวณ) ไม่ส่งออกไปบริการอื่นโดยไม่ได้อธิบาย
- บันทึกการละหมาดรายเวลา (ถ้าเปิด): ใช้ตัวเลือกกลาง "ทำแล้ว/ยัง" ไม่มี streak ไม่มีสถิติเปรียบเทียบ ไม่แสดงบน Today
- ปิดโมดูล = ซ่อน; ลบข้อมูลศาสนาได้แยกจาก Settings (ปุ่ม "ลบข้อมูล Faith ทั้งหมด")
- เนื้อหาศาสนา (ข้อความ/ชื่อวัน) ต้องผ่านการตรวจจากผู้รู้หรือเพื่อนมุสลิมอย่างน้อย 1 คนก่อนปล่อย

## 9.6 Tests

1. `PrayerTimes` ตรงกับตารางอ้างอิง ≤ ±1 นาทีในอย่างน้อย 3 เมืองที่ผู้พัฒนาตรวจเอง (บันทึกข้อมูลอ้างอิงใน `tests/fixtures`)

# 13. เพิ่มใน §50 Known Limitations

- Month view ไม่มีเวลาในวัน และไม่มีการลากย้ายงาน
- เวลาละหมาดและวันที่ฮิจเราะห์เป็นค่าคำนวณ อาจต่างจากประกาศท้องถิ่น ผู้ใช้ต้องเลือกวิธีและปรับวันเอง
- ยังไม่มีการจัดตารางอัตโนมัติรอบเวลาละหมาด (ไม่มี time-blocking)
- ไม่มีการแจ้งเตือนจริง (push/อีเมล) จนกว่าจะทำ PWA
- Reflection ไม่มี PIN/เข้ารหัสแยกชั้น ใช้การล็อกอินของบัญชีเท่านั้น
- ข้อมูลศาสนาในโมดูลควรผ่านการตรวจจากผู้รู้ก่อนใช้งานจริง

# 14. สิ่งที่พูดตอน present (เพิ่มใน §54 / ข้อ 10 ของโครงรายงาน)

- **จุดต่างจากแอปอื่น:** ไม่แข่งที่จำนวนฟีเจอร์ แต่แข่งที่ "รู้จักชีวิตนักศึกษา": ประเภทงาน (สอบ ≠ การบ้าน), Exam Mode, เกรดเป้าหมาย, แยกเรียน/ส่วนตัว, เริ่มใช้ได้ใน 2 นาที
- **ความง่าย:** ผู้ใช้ใหม่เห็น 4 แท็บ; ฟีเจอร์เสริมเป็นโมดูลที่เลือกเปิด
- **การออกแบบเพื่อขยาย:** เพิ่มโมดูลใหม่ = เพิ่มคลาสลูกของ `Module` หนึ่งตัวและ `@register` หนึ่งบรรทัด (polymorphism + registry) ไม่แก้โค้ดเดิม
- **ความรับผิดชอบต่อกลุ่มผู้ใช้:** Faith ไม่เดาวิธีคำนวณ ให้ผู้ใช้เลือก, ไม่ตัดสินการปฏิบัติ, ข้อมูลศาสนาเป็นส่วนตัวและลบได้
- **คำถามที่น่าจะโดนเพิ่ม:** ทำไมไม่ใส่ฟีเจอร์ครบใน v1 (ตอบ: คุณภาพของแกน, tests, และเวลา — roadmap อยู่ในรายงาน); ทำไมโมดูลแยกจาก `domain.py`; เวลาละหมาดคำนวณอย่างไรและแม่นแค่ไหน
